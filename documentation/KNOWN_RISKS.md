# Known risks and rollout gates

## P0: before student requests, student data and circulation

- The new request graph permits Pending → Approved/Declined/Issued and Approved → Issued/Declined. Students may only cancel their own Pending request. Issued, Declined and Cancelled are terminal; reopening requires a new request. Every decision needs a bounded note, server timestamp, ISO display timestamp and the current actor UID.
- Administrative authorization/profile removal is staff-only and must include its recovery journal. The portal now requests removal instead of deleting institution-controlled records directly. Complete a removal only after active access/profile records are absent. Historical circulation, admission reservations and recovery/audit copies need an institution retention decision.
- Access numbers resolve case-insensitively and preserve canonical references. One active loan per copy is enforced in SQLite. Damage/restoration requires closing the active loan first. Legacy duplicate IDs or concurrent active loans must be reconciled from backups before opening live circulation; do not drop the uniqueness indexes to bypass conflicts.
- Deploy the changed clients and generated rules together. Older clients omit the new decision/audit protocol and will be rejected by hardened rules. Published v1.0.9 installers have not been silently replaced. The previously deployed project rules are not evidence that this newer hardening protocol is active.

## P1: before broader administrative use and distribution

- Audit events include actor, server time, target and before/after data and cannot be edited/deleted by clients. Protected configuration, appearance, grants, roster/claims and kiosk changes validate their matching event atomically. Receipt reads and snapshot publication are separate workflows; direct Firebase IAM/Admin SDK operations bypass client rules and need the institution's Cloud audit/IAM controls.
- Admin shows recent journal entries and can restore deleted profile/access/roster records without overwriting a current record or stealing an admission claim. Recovery archives are not permanent-erasure functionality. Set an institution retention/purge policy and limit staff access to archives.
- Control Center is deliberately operator-managed: public stable checks, no automatic download/install-on-quit, no downgrade/prerelease, explicit install, checksum/signature recheck and successful checkpoint. It is not governed by Admin/Librarian institution approval documents. Unsigned pilot mode is labelled as such; publisher authenticity needs existing trust keys/certificates supplied by the publisher.
- Source/tag/version/SBOM checks gate publication. Do not publish this dirty development tree as a new release, overwrite published installers, or treat preview SBOM provenance as a clean release attestation.
- Updated kiosk storage requires reactivation of old unscoped credentials. Secure OS storage must be available; Linux basic-text storage is rejected. Credential binding does not protect against malware running as the same OS user. Desktop IPC remains restricted to its local main frame and lock state, with size/rate bounds; those are not OS isolation.

## P2: before large-library deployment and open-source promotion

- Local catalogue, students, transactions and fines use bounded 25-row render windows; SQLite FTS5 supports word/prefix search and overdue/status indexes avoid full transaction scans. The measured fixture is 10,000 books, not a production-scale benchmark across all supported machines. FTS search is word/prefix based, not arbitrary substring matching.
- Admin circulation/catalogue pages load 25 at a time and use a bounded temporary cache. Administrative roster/access/profile lists use live server cursor windows (25 records plus one lookahead); prefix search uses email or admission document IDs. Pending profiles use at most two direct ownership/roster reads per row, and verified profiles are hidden within each window. A page with no waiting profiles can still have further pages. Admission ownership is always checked again in the save transaction. Institutional-size quota/latency benchmarks remain a deployment gate.
- Snapshot sync still builds a complete publication in memory. Fifty-row sequential uploads bound each server commit but do not make snapshots incremental or resolve multi-desk conflicts. Public Firestore quotas, backup storage, plaintext circulation exports, FTS index disk growth and archive retention need operational capacity planning.
- Windows 7/8.1 uses a legacy Electron runtime and an obsolete OS security baseline. A successful legacy runtime test on a modern machine is not Windows 7 hardware/security acceptance.
- Dependency SBOMs include metadata and build inputs. Review unknown licenses and upstream runtime notices before redistribution. No hosted CI run, independent penetration test, availability SLA or regulatory compliance claim follows from local test success.

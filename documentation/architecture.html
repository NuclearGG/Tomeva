Tomeva / current source architecture

Four applications.
One institution-owned system.

Control Center configures and distributes the system. Librarian keeps circulation in local SQLite. Admin governs access and rollout. The hosted Student Portal lets authorized accounts browse and request books.

01 / Control Center

Set up and distribute

Configuration stays with the institution. Release installers and the Student Portal archive come from GitHub and are verified before packaging.

  1. InputInstitution setupFirebase web config, staff domain, optional HTTPS site URL
  2. Local actionGenerate setupRules, indexes, desktop configuration, encrypted recovery kit
  3. DownloadGitHub ReleasesMatching modern or legacy installers and Student ZIP, checked by size and SHA-256
  4. OutputConfigured exportsAdmin and Librarian folders plus deployable Student site

Publishing generated Firestore rules and hosting the Student site are separate institution actions. The Control Center installer contains no other app installers.

02 / Librarian

Circulation stays local

Loans, returns, fines, students, and catalogue changes run through Electron main-process IPC into SQLite. A workstation PIN protects the desk.

  1. DeskLibrarian UIBook and student actions, requests, backups
  2. BoundaryPreload + IPCValidated methods and local business rules
  3. RecordSQLite + WALBooks, students, transactions, fine payments, settings
  4. When onlineFirebase syncPublic catalogue; protected circulation with approved kiosk credentials

The local SQLite database is the circulation source of truth. Internet outages do not stop desk issue and return operations.

03 / Admin

Govern access and rollout

Admin is an Electron app. Verified staff sign in through the institution's Firebase project; Firestore rules enforce the permissions behind its UI.

  1. IdentityGoogle sign-inVerified email in configured staff domain
  2. RosterAdmission recordsCSV/JSON pre-registration and unique admission reservations
  3. AccessFirestoreAuthorized students, pending profiles, kiosk registrations
  4. UpdatesApproval policyApproved version, rollout time and pause state for desktop apps

Admin reads synchronized catalogue and circulation summaries. It does not replace the Librarian's local database.

04 / Student Portal

Search and request

The institution hosts static HTML over HTTPS. Google sign-in and an authorized student record or staff-domain match unlock the portal.

  1. IdentityFirebase AuthBrowser session expires after 10 hours
  2. ReadPublic catalogueSearch current book availability
  3. WriteAtomic request + quotaOne Firestore transaction counts up to 100 book requests per account per 10 hours
  4. Follow-upRequests + messagesTrack decisions, cancel pending requests, manage account

The quota is enforced by Firestore rules and requires deploying the updated institution rules. Static assets and catalogue reads are not counted as book requests.

Local data

Librarian SQLite, its backups and activity logs remain on the desk computer. Control Center recovery kits contain configuration, not circulation records.

Cloud data

Each institution owns Firebase Auth, Firestore, security rules and Student hosting. The public catalogue is separate from restricted circulation data.

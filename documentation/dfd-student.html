Libra · Data Flow Diagram

Student Interface — Verify, Then See

The browser portal students and teachers use to check availability and request a book. No data is visible until sign-in resolves to a verified identity — either a staff email domain, or a student explicitly authorized by admin. Group membership is never a self-declared field.

External Entity — a person or outside data source
Process — an action the app performs
Data Store — where information is kept
The dashed-border process: Process 3 (Complete Profile) only fires for a first-time, unverified sign-in — it collects Class + ADM No so admin can identify who's waiting, but it does not grant access on its own. The visitor still lands on "Access Pending" afterward.
Reading this diagram: Process 2 (Verify Identity) is the gate — nothing downstream runs until it resolves. The colored arrow into Process 5 shows the one flow a Firestore rule independently re-checks, since the client-side Group field is locked, not just hidden.
